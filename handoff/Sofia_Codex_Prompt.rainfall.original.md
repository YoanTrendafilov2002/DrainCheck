# Build the Sofia terrain, sewer and rainfall explorer

Build a working standalone web app from the attached `sofia_app_handoff` package. Implement and test it; do not stop at a plan, mockup, or scaffold. The existing Google Earth Engine prototype is the behavior reference, but the delivered app should have its own responsive interface and run locally from documented commands.

Start with `README.md`, `docs/DATA_CONTRACT.md`, `docs/ACQUISITION.md`, `docs/RAINFALL.md`, `config/map_config.json`, and `data/derived/summary.json`. Preserve the original files, the two Earth Engine scripts, and the newly supplied rainfall script. The latter is included byte-for-byte as `earth_engine/Rainfall_20250627_original.js`; use it as the rainfall behavior reference while retaining the newer granular terrain normalization. Work in a new app directory or an appropriate branch of an existing repository. Do not delete or overwrite source data.

## Goal and limits

Create a map for exploring Sofia ground elevation, actual supplied sewer route geometry, green areas, infrastructure points, and the supplied daily rainfall event for 27 June 2025. This is a terrain/infrastructure explorer and a foundation for later drainage studies. It is not a validated flood-risk or sewer-capacity model. Do not invent flood depths, pipe capacities, invert elevations, flow direction, connectivity, additional rainfall events or time series, or risk scores from the available data.

Imperviousness was explicitly removed from the active map. Do not add it back. Keep the source provenance and dates visible: sewer routes are a 2009 source, green areas a 2020 source, and the municipal DTM is listed valid at 2024-10-01. These dates do not establish current field conditions.

## Architecture

If there is an existing suitable app stack, reuse it. Otherwise use React + TypeScript + MapLibre GL JS for the frontend and a small Python API for spatial queries and elevation/tiles. Keep the app modular, with data preparation separate from serving and UI. This proposed stack is a starting point, not a demand to introduce unnecessary services.

Use the prepared GeoJSON and the three bundled numeric rainfall COGs immediately. All 55 rain-station features and the full values/masks of the three rainfall assets are now included; they do not require Earth Engine credentials. For production rendering, build indexed vector data or vector tiles and serve raster tiles; avoid loading the full 1 m raster or all large vectors into the main browser thread. Retain high-resolution geometry for inspection and exports even if a low-zoom display layer is simplified. Do not reproduce the prototype's large compressed vector strings in the frontend JavaScript bundle.

Provide a local COG-backed elevation adapter, with optional authenticated Earth Engine backend access where available. The full DTM and infrastructure-point binaries are NOT in this package; their exact asset IDs and acquisition tools are provided. First inspect available authorized credentials/files. If missing, continue all independent work with the real included vectors and rainfall, wire the backend interfaces, show a clear unavailable state for those layers, and report exactly what access or files are needed. Never fabricate data, substitute the preview PNG for the DTM, or silently replace the 1 m municipal raster with SRTM/Copernicus DEM. Keep credentials on the server, outside source control and client bundles.

## Required behavior

1. Display a usable full-screen map with collapsible controls, a continuous elevation legend in metres, a coordinate/elevation inspector, source details, layer opacity, and loading/error states. Controls must not obscure most of the map. Make it usable on desktop and mobile. Make the basemap configurable and retain attribution.
2. Preserve the municipal DTM's native 1 m grid for scientific values and pixel readouts. Horizontal CRS: EPSG:7801; affine transform `[1,0,299392,0,-1,4753611]`; vertical datum: Baltic 1982 (EPSG:5786). The reference PNG is a 10 m averaged preview in UTM 34N, not the native data. Web display reprojection/overviews must never replace the native analysis raster. One-metre cell size is not a claim of vertical accuracy.
3. Use the reference palette: `0b4da2,27a7df,6ddcc7,83ca42,d7e865,fff2a3,f6bd60,e76f51,b53252`. Give small elevation changes visible colour detail using the provided continuous 201-point percentile normalization. Port or reuse `shared/elevation_scale.mjs`. Preserve real heights. Do not discretize heights into 201 bands or reinstate the old 553–598 m fixed stretch. Whole-study-area normalization is the stable default; provide explicit local fit, reset to whole-area scale, and opt-in auto-fit. Pan/zoom must not silently change colours with auto-fit off. Clearly label the nonlinear scale and its scope. Compute inverse-mapped metre ticks, not evenly spaced height labels on a nonlinear ramp. Use `data/reference/elevation_quantiles_whole_area.json` for the supplied full curve; do not substitute the five rounded observed legend labels. Recompute only when the data revision or normalization scope changes.
4. Preserve native NoData/coverage masks. Missing data must remain missing, not zero-filled as a real height, interpolated, or extrapolated into invented terrain. Distinguish no data, loading, and request errors. Include toggleable hillshade with the existing 315° azimuth / 45° illumination as the reference.
5. Show the 717 supplied sewer routes with existing/planned/open status toggles. Match cyan existing, dashed magenta planned, yellow open. Preserve all original properties and source IDs. Do not infer routes from the infrastructure points. Default to pipe sections inside green areas; also allow outside and all. Use one zone at a time so the duplicated representations are not double-counted.
6. Use all 64,956 nonempty green polygons for the spatial mask. The 2,175 prepared polygons intersecting routes are a display subset, not the complete analysis mask. Preserve polygon holes, multipart geometry, and line traversal multiplicity. Include a green-layer toggle and access to the full source layer where useful. Keep the six empty original records and the original invalid polygon in raw files; repair/exclude only derived processing copies and record that provenance.
7. Show count and total length for the selected zone and enabled statuses. The count is the number of represented source routes, not the number of disconnected line pieces. The same source can occur in both inside and outside representations. Provide route click details and export of the selected route sections with IDs/properties.
8. Retain optional infrastructure point layers, initially off. Load them when authorized data becomes available, with the supplied category definitions, counts, and separate treatment of missing type. Use indexing/tiling or viewport requests for 322,025 points.
9. Preserve map view, enabled layers, route filters, and colour-scale scope in shareable app URL state. Store/reuse whole-area statistics rather than recalculating the whole raster on each pan. Debounce local-fit requests, cancel/ignore stale responses, and cache tiles/statistics by dataset revision and scale definition.

## Rainfall and water data — required addition

Integrate the actual data in `data/rainfall/` and follow `docs/RAINFALL.md`. Keep all prior terrain, green-mask and sewer requirements. The attached rainfall script is an additional preserved reference, not a replacement for Script1/Script2 or an instruction to restore its older P2–P98 elevation stretch/default auto-fit.

- Load the included merged and bias-corrected nominal 250 m daily rainfall COGs (104 × 71 cells each), raw nominal 1 km daily-radar COG (98 × 69), and all 55 stations (43 accepted / 12 rejected). Their actual stored CRS is EPSG:4326 with distinct exact affine grids. Preserve native values, coverage and masks. The product labels are not a claim of exact square metric cells or independently observed 250 m resolution.
- Date: 2025-06-27 local day, Europe/Sofia. Unit: accumulated mm, not mm/hour. Do not create a five-minute animation: only daily products are supplied. The original radar/station time series and upstream processing programs are unavailable, although named in provenance.
- Add final/corrected/raw selection, rainfall visibility and opacity, independent station filters, rainfall legend, native click readout, and summary statistics. Default to final merged, accepted stations visible and rejected hidden. Keep terrain/route/green toggles independent and preserve the earlier infrastructure-point default off. Include rainfall state in the URL.
- Use the continuous rainfall palette and stable ranges in `map_config.json`: 0–30 mm final/corrected, 0–110 mm raw. Optional bilinear display smoothing must not alter native sampling, statistics or mask coverage. Provide a native-cell view. Show the final layer's source display threshold of 0.5 mm as an explicit adjustable/disableable control; it must never discard low rainfall from analysis or export.
- Station details retain station_id, rain_mm, qc and rows, including every rejected value/reason. Preserve QC classifications; do not invent a new QC or correction algorithm. Do not apply another bias correction to the provided corrected/final layers. The source script's approximate fourfold raw bias is an unverified provenance claim, not a universal correction factor.
- Summaries use valid-cell area, an area-weighted mean, and `sum(rain_mm / 1000 * cell_area_m2)` for **precipitation volume**. Geographic cells need appropriate geodesic/ellipsoidal area calculations. State the geographic scope, coverage area and partial-cell rule for selections. Do not label this runoff, sewer loading, floodwater volume, or flood depth.
- Water-supply infrastructure remains a distinct optional category (40,994 original points in the unbundled infrastructure asset). Rain stations, water-supply points and sewer route lines must not be conflated or connected by invented geometry.
