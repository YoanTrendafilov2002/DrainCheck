# Build the Sofia terrain and sewer explorer

Build a working standalone web app from the attached `sofia_app_handoff` package. Implement and test it; do not stop at a plan, mockup, or scaffold. The existing Google Earth Engine prototype is the behavior reference, but the delivered app should have its own responsive interface and run locally from documented commands.

Start with `README.md`, `docs/DATA_CONTRACT.md`, `docs/ACQUISITION.md`, `config/map_config.json`, and `data/derived/summary.json`. Preserve the original files and the two Earth Engine scripts. Work in a new app directory or an appropriate branch of an existing repository. Do not delete or overwrite source data.

## Goal and limits

Create a map for exploring Sofia ground elevation, actual supplied sewer route geometry, green areas, and infrastructure points. This is a terrain/infrastructure explorer and a foundation for later drainage studies. It is not a validated flood-risk or sewer-capacity model. Do not invent flood depths, pipe capacities, invert elevations, flow direction, connectivity, rainfall, or risk scores from the available data.

Imperviousness was explicitly removed from the active map. Do not add it back. Keep the source provenance and dates visible: sewer routes are a 2009 source, green areas a 2020 source, and the municipal DTM is listed valid at 2024-10-01. These dates do not establish current field conditions.

## Architecture

If there is an existing suitable app stack, reuse it. Otherwise use React + TypeScript + MapLibre GL JS for the frontend and a small Python API for spatial queries and elevation/tiles. Keep the app modular, with data preparation separate from serving and UI. This proposed stack is a starting point, not a demand to introduce unnecessary services.

Use the prepared GeoJSON immediately. For production rendering, build indexed vector data or vector tiles and serve raster tiles; avoid loading the full 1 m raster or all large vectors into the main browser thread. Retain high-resolution geometry for inspection and exports even if a low-zoom display layer is simplified. Do not reproduce the prototype's large compressed vector strings in the frontend JavaScript bundle.

Provide a local COG-backed elevation adapter, with optional authenticated Earth Engine backend access where available. The full DTM and infrastructure-point binaries are NOT in this package; their exact asset IDs and acquisition tools are provided. First inspect available authorized credentials/files. If missing, continue all independent work with the real included vectors, wire the backend interfaces, show a clear unavailable state for those layers, and report exactly what access or files are needed. Never fabricate data, substitute the preview PNG for the DTM, or silently replace the 1 m municipal raster with SRTM/Copernicus DEM. Keep credentials on the server, outside source control and client bundles.

## Required behavior

1. Display a usable full-screen map with collapsible controls, a continuous elevation legend in metres, a coordinate/elevation inspector, source details, layer opacity, and loading/error states. Controls must not obscure most of the map. Make it usable on desktop and mobile. Make the basemap configurable and retain attribution.
2. Preserve the municipal DTM's native 1 m grid for scientific values and pixel readouts. Horizontal CRS: EPSG:7801; affine transform `[1,0,299392,0,-1,4753611]`; vertical datum: Baltic 1982 (EPSG:5786). The reference PNG is a 10 m averaged preview in UTM 34N, not the native data. Web display reprojection/overviews must never replace the native analysis raster. One-metre cell size is not a claim of vertical accuracy.
3. Use the reference palette: `0b4da2,27a7df,6ddcc7,83ca42,d7e865,fff2a3,f6bd60,e76f51,b53252`. Give small elevation changes visible colour detail using the provided continuous 201-point percentile normalization. Port or reuse `shared/elevation_scale.mjs`. Preserve real heights. Do not discretize heights into 201 bands or reinstate the old 553–598 m fixed stretch. Whole-study-area normalization is the stable default; provide explicit local fit, reset to whole-area scale, and opt-in auto-fit. Pan/zoom must not silently change colours with auto-fit off. Clearly label the nonlinear scale and its scope. Compute inverse-mapped metre ticks, not evenly spaced height labels on a nonlinear ramp. Use `data/reference/elevation_quantiles_whole_area.json` for the supplied full curve; do not substitute the five rounded observed legend labels. Recompute only when the data revision or normalization scope changes.
4. Preserve native NoData/coverage masks. Missing data must remain missing, not zero-filled as a real height, interpolated, or extrapolated into invented terrain. Distinguish no data, loading, and request errors. Include toggleable hillshade with the existing 315° azimuth / 45° illumination as the reference.
5. Show the 717 supplied sewer routes with existing/planned/open status toggles. Match cyan existing, dashed magenta planned, yellow open. Preserve all original properties and source IDs. Do not infer routes from the infrastructure points. Default to pipe sections inside green areas; also allow outside and all. Use one zone at a time so the duplicated representations are not double-counted.
6. Use all 64,956 nonempty green polygons for the spatial mask. The 2,175 prepared polygons intersecting routes are a display subset, not the complete analysis mask. Preserve polygon holes, multipart geometry, and line traversal multiplicity. Include a green-layer toggle and access to the full source layer where useful. Keep the six empty original records and the original invalid polygon in raw files; repair/exclude only derived processing copies and record that provenance.
7. Show count and total length for the selected zone and enabled statuses. The count is the number of represented source routes, not the number of disconnected line pieces. The same source can occur in both inside and outside representations. Provide route click details and export of the selected route sections with IDs/properties.
8. Retain optional infrastructure point layers, initially off. Load them when authorized data becomes available, with the supplied category definitions, counts, and separate treatment of missing type. Use indexing/tiling or viewport requests for 322,025 points.
9. Preserve map view, enabled layers, route filters, and colour-scale scope in shareable app URL state. Store/reuse whole-area statistics rather than recalculating the whole raster on each pan. Debounce local-fit requests, cancel/ignore stale responses, and cache tiles/statistics by dataset revision and scale definition.

## Validation and delivery

Run the supplied handoff verification and scale tests first. Add meaningful integration tests for geometry partitioning, filter statistics, native-coordinate elevation sampling, NoData, nonlinear legend inversion, stale local-fit responses, and URL state. Use real included data for the initial end-to-end vector map, not placeholder features.

Baseline checks: all routes 717 / 540.1630135 km; inside 543 / 137.8586989 km; outside 670 / 402.3043147 km. Counts are not additive, lengths are additive within numerical tolerance. Status totals are 464 existing, 250 planned, 3 open. Use `summary.json` for more precise values. Raw green records: 64,962, of which 64,956 are nonempty, with one invalid geometry repaired in derived processing. Point asset expected count: 322,025.

Inspect rendered screenshots at regional and close-up scales. Verify no unintended broad endpoint-colour saturation, no hidden/missing tiles disguised as valid terrain, and no incorrect height legend. If the user pans beyond a locked local scale, preserve the scale and clearly offer fit/reset; do not silently enable auto-fit. Preserve the distinction between coarse display statistics and native one-metre samples.

Deliver the running app source, reproducible preparation and serving commands, dependency lockfiles, example environment configuration without secrets, tests with results, concise architecture/data notes, and deployment instructions. Report which inputs were actually loaded, which remain unavailable, and any failed checks. Do not publish publicly or provision paid infrastructure merely to complete the local build. If a credential or external file is the only blocker, finish all other work and give the exact next command/file placement needed.
